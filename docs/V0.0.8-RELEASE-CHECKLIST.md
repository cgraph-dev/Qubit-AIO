# Qubit v0.0.8 release checklist — prewarm/warm-read cache delta

**Status:** release checklist. Not a `VERIFIED` verdict and not a publish
instruction. The version is already declared `0.0.8`; this branch does not bump
it, create a tag, publish a release, or restart a service.

The machine gate is `scripts/release_fresh_install_gate.py`, wired into
`scripts/prepare_production_release.py` and `scripts/promote_public_release.py`.
`scripts/verify_public_release.py --require-platform-assets` checks the
published asset set. A release is refused when any check below is false.

| Installed dashboard assets ship | `dashboard_assets`, `wheel_dashboard_assets` | `frontend/qubit-dist/index.html` in tree/wheel |

| **Prewarm/warm-read contract holds** | `prewarm_cache_contract` | `WebUI.start` calls `_prewarm_reads` (gated by `QUBIT_WEBUI_PREWARM`), which primes all six slow handlers; every slow read namespace keeps a TTL of at least 60 s |

Exit codes are typed: `0` PASS, `2` FAIL, `4` DEGRADED, `8` BLOCKED. A
DEGRADED fresh-install is never rewritten to PASS; preparation runs with
`--require-fresh-install`, so DEGRADED blocks the release.

  --repo cgraph-dev/Qubit --tag v0.0.8 --require-platform-assets

gh release edit v0.0.8 --repo cgraph-dev/Qubit --draft=false --latest

## Blockers / not claimed

1. **No v0.0.8 built release inputs.** Only `/tmp/qubit-production-release-v007`
   (0.0.7) and older directories exist. The static gate therefore fails on the
   missing dashboard bundle, which `prepare_production_release.py` builds before
   running the full gate. This is expected pre-build, not a defect.
2. **No v0.0.8 tag or release.** `git tag` in this checkout lists only `v0.0.1`;
   the production repo must be checked before promotion.
3. **Draft workflow asset gap (fixed here).** `.github/workflows/promote-release.yml`
   previously uploaded only the wheel/sdist/checksums/manifest/notes/summary,
   omitting `bootstrap.sh`, `bootstrap.ps1`, `install.sh`, `install.ps1`,
   `qubit-release.tar.gz`, and `qubit-release.zip`. A draft created by that
   workflow could not pass `verify_public_release --require-platform-assets`.
   The workflow now uploads all 12 assets; `tests/test_production_release.py`
   pins the list.
4. **Fresh-install probe needs a real install** (network for Python
   dependencies, Node/npm for the dashboard). Without it the gate is DEGRADED,
   and preparation with `--require-fresh-install` refuses.
5. **Real Windows/macOS execution, signing, live-service behavior, and
   GitHub-hosted CI remain manual/unproven** and are not claimed by this
   checklist. Windows execution is out of scope per `docs/DECISIONS.md`
   ruling 11.
