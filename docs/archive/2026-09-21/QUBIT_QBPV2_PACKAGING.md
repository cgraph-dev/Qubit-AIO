## 1. Launcher repair (operator shim)

The operator shim `~/.local/bin/qubit` was stale: it `cd`-ed a non-existent
sibling checkout (`~/Projects/Repos/Qubit (2)`) and `exec`-ed
`~/Projects/Repos/voice-dashboard/open.sh` (a browser opener for a foreign
dashboard). It shadowed the authoritative repo console script on PATH in any
shell where the checkout venv was not first.

Original bytes were recorded before any change:

| | value |
|---|---|
| path | `~/.local/bin/qubit` |
| mode | `0711` |
| size | 298 bytes |
| sha256 | `bc6bec0b06f5ce1c7ffba2bafb8c2b26c1a29e5c11a642b27218d06239f486c6` |
| evidence | `/tmp/opencode/qbpv2/evidence/qubit.launcher.orig` |

The replacement is generated by the repo's own install mechanism
(`scripts/install.sh --launcher-only`, called automatically by a normal
install). It delegates to the authoritative checkout's canonical console
script (`<repo>/.venv/bin/qubit`, from `pyproject.toml`
`[project.scripts] "qubit = voicebridge.cli:main"`), resolved at install time —
never a hand-typed stale path. Resolution order:

1. `$QUBIT_REPO/.venv/bin/qubit` (explicit operator override);
2. the authoritative checkout baked in by `scripts/install.sh` at install time;
3. a real `qubit` console script elsewhere on `PATH` (skipping the shim's own
   directory, so it can never recurse into itself).

If none resolves, it exits `127` with a typed message. The installer is
idempotent and backs up a divergent pre-existing shim (timestamped
`qubit.bak.<ts>`) instead of silently clobbering it.
