# Qubit v0.0.7 release checklist — fresh-install + perf/cache contract

**Status:** release checklist. Not a `VERIFIED` verdict, not a publish
instruction. This branch does not bump the version; it records what the v0.0.7
gate must prove before the lead tags or publishes.

The machine gate is `scripts/release_fresh_install_gate.py`, wired into
`scripts/prepare_production_release.py` and `scripts/promote_public_release.py`.
`scripts/verify_public_release.py --require-platform-assets` checks the
published asset set. A release is refused when any check below is false.

| Contract | Gate check(s) | Evidence |
|---|---|---|
| Installed dashboard assets ship | `dashboard_assets`, `wheel_dashboard_assets` | `frontend/qubit-dist/index.html` in tree/wheel |
| Bundled TUI entry ships | `tui_dist_entry`, `wheel_tui_dist_entry` | `qubit_runtime/ui-tui/dist/entry.js` |
| Packaged TUI resolves without a source build | `packaged_tui_no_source_build`, `wheel_packaged_tui` | `_make_tui_argv` resolves `dist/entry.js` without `scripts/build/node-deps.mjs` |
| Fresh install seeds a root `config.yaml` | `fresh_install_root_config` | `<prefix>/config.yaml` after a throwaway install |
| That config is a working local Ollama default | `config_default_ollama`, `fresh_install_ollama_provider` | `model.provider: ollama` (or localhost `custom` base URL) |
| Static perf/cache contract holds | `perf_cache_static_contract` | hashed `assets/` served `public, max-age=31536000, immutable`; token-bearing shell uses the `_send` `no-store` default and never opts into a cache; gzip body cache present |
| POSIX assets present and consistent | `release_assets`, `release_checksums`, `archive_posix_installer` | `bootstrap.sh`, `install.sh`, `qubit-release.tar.gz`, `SHA256SUMS` |
| Windows assets present and consistent | `release_assets`, `release_checksums`, `archive_windows_installer` | `bootstrap.ps1`, `install.ps1`, `qubit-release.zip` |
| Public verifier passes for the built release | `verify_public_release` | `verify_public_release.py --require-platform-assets` |

Exit codes are typed: `0` PASS, `2` FAIL, `4` DEGRADED, `8` BLOCKED. A
DEGRADED fresh-install is never rewritten to PASS; preparation runs with
`--require-fresh-install`, so DEGRADED blocks the release.

## Cut sequence (lead, after this branch merges)

```bash
# 1. Bump the five version homes to 0.0.7, then commit the bump.
#    VERSION, pyproject.toml [project].version, voicebridge/__init__.py,
#    voicebridge/product.py PRODUCT_VERSION, voicebridge/distribution.py
#    PACKAGE_VERSION — all must agree.
grep -rn '0\.0\.6' VERSION pyproject.toml voicebridge/__init__.py \
  voicebridge/product.py voicebridge/distribution.py   # expect none
git status --short                                      # clean before build

# 2. Build the dashboard bundle (git-ignored) and write build info.
KEEP_NODE_MODULES=1 bash scripts/build_dashboard.sh
node frontend/qubit-web/scripts/write-build-info.mjs

# 3. Prepare + gate every asset (refuses dirty tree, won't move a tag).
python3 scripts/prepare_production_release.py \
  --out /tmp/qubit-production-release-0.0.7 --tag v0.0.7 --verify

# 4. Inspect the gate's report.
python3 - <<'PY'
import json
print(json.load(open("/tmp/qubit-production-release-0.0.7/release-gate-report.json"))["verdict"])
PY

# 5. Re-verify the built release read-only (fresh install into a throwaway prefix).
python3 scripts/release_fresh_install_gate.py \
  --repo . --release-dir /tmp/qubit-production-release-0.0.7 \
  --fresh-install --require-fresh-install --json

# 6. Promote to production (dry-run first; add --apply to push, --push-tag to tag).
python3 scripts/promote_public_release.py \
  --source-commit "$(git rev-parse HEAD)" --version 0.0.7 \
  --remote-url https://github.com/cgraph-dev/Qubit.git
#    ...then the same line with --apply --push-tag when the dry-run is clean.

# 7. Consumer-side verification of the published release.
python3 scripts/verify_public_release.py \
  --repo cgraph-dev/Qubit --tag v0.0.7 --require-platform-assets
```

## Checks that remain manual (not claimed PASS)

1. **Real Windows execution.** `bootstrap.ps1`/`install.ps1` under Windows
   PowerShell 5.1, extraction/checksums, `%LOCALAPPDATA%\qubit`, uninstall and
   update. The gate checks asset presence and ZIP/installer consistency only.
2. **Real macOS execution.** LaunchAgent install/start/restart and the typed
   voice-unsupported path; macOS is not wired into the gate.
3. **Signed artifacts.** v0.0.7 stays the explicit unsigned exception unless the
   owner supplies an approved signer fingerprint and `--sign`/`--verify-signatures`.
4. **Live service behavior.** The gate installs into a throwaway prefix/HOME and
   never starts a service. Cache headers are proven statically from source; the
   running dashboard must be exercised separately if a live check is wanted.
5. **GitHub-hosted CI.** The gate and workflow steps exist, but hosted runners
   remain subject to the account-level Actions blocker in `docs/STATUS.md`.
