## Rule enforcement

The generator fails (non-zero exit) rather than emit a row that:

1. claims `ported` or `partial` with `our_lines == 0` (the fabrication
   signature: a file asserted as present with nothing behind it);
2. claims `declined` with empty `notes` (a silent gap dressed as a decision);
3. claims `rewired` without naming what was replaced and with what;
4. claims `ported` without a recorded normalised comparison (top-level
   defs, route strings, response keys);
5. desynchronises the row count from `git ls-files` on any clone;
6. carries an empty or undefined `status`.

`python scripts/parity_ledger.py --check` regenerates in memory and compares
against the committed files, so a ledger that has drifted from its inputs
fails visibly instead of being trusted.
