# Qubit v0.0.6 release checklist — the fresh-install contract

**Status:** release checklist. Not a `VERIFIED` verdict and not a publish
instruction. The version is not bumped here; this file records what the v0.0.6
release gate must prove before the owner tags or publishes.

The machine gate is `scripts/release_fresh_install_gate.py`. It is wired into
`scripts/prepare_production_release.py` and `scripts/promote_public_release.py`,
and `scripts/verify_public_release.py --require-platform-assets` checks the
published asset set. A release is refused when any of these is false:

| Check | Gate name | Evidence |
|---|---|---|
| Installed dashboard assets are shipped | `dashboard_assets`, `wheel_dashboard_assets` | `frontend/qubit-dist/index.html` in the tree/wheel |
| The bundled TUI entry is shipped | `tui_dist_entry`, `wheel_tui_dist_entry` | `qubit_runtime/ui-tui/dist/entry.js` |
| A packaged install does not rebuild the TUI from source | `packaged_tui_no_source_build`, `wheel_packaged_tui` | `_make_tui_argv` resolves `dist/entry.js` without `scripts/build/node-deps.mjs` |
| A fresh install seeds a root `config.yaml` | `fresh_install_root_config` | `<prefix>/config.yaml` after a throwaway install |
| That config names a working local Ollama default | `config_default_ollama`, `fresh_install_ollama_provider` | `model.provider: ollama` (or a localhost `custom` base URL) |
| POSIX assets are present and consistent | `release_assets`, `release_checksums`, `archive_posix_installer` | `bootstrap.sh`, `install.sh`, `qubit-release.tar.gz`, `SHA256SUMS` |
| Windows assets are present and consistent | `release_assets`, `release_checksums`, `archive_windows_installer` | `bootstrap.ps1`, `install.ps1`, `qubit-release.zip` |
| The public verifier passes for the built release | `verify_public_release` | `scripts/verify_public_release.py --require-platform-assets` |

## Commands

```bash
# 1. The checkout must be clean; the gate refuses a dirty tree in prepare.
git status --short

# 2. Prepare every asset and run the gate (this is the required path).
python3 scripts/prepare_production_release.py \
  --out /tmp/qubit-production-release --tag v0.0.6 --verify

# 3. Inspect the gate's own report.
python3 - <<'PY'
import json
p = "/tmp/qubit-production-release/release-gate-report.json"
print(json.load(open(p))["verdict"])
PY

# 4. Re-verify the built release base read-only.
python3 scripts/release_fresh_install_gate.py \
  --repo . --release-dir /tmp/qubit-production-release \
  --fresh-install --require-fresh-install --json

# 5. Consumer-side read-only verification of a published release.
python3 scripts/verify_public_release.py \
  --repo cgraph-dev/Qubit --tag v0.0.6 --require-platform-assets
```

Exit codes are typed: `0` PASS, `2` FAIL, `4` DEGRADED, `8` BLOCKED. A
DEGRADED fresh-install check is never rewritten as PASS; release preparation
runs with `--require-fresh-install`, so DEGRADED blocks the release.

## Checks that remain manual

These cannot be proven by the gate from this host and are **not** claimed as
PASS:

1. **Real Windows execution.** `bootstrap.ps1`/`install.ps1` under Windows
   PowerShell 5.1, real extraction/checksum handling, `%LOCALAPPDATA%\\qubit`
   layout, launcher, and uninstall/update. The gate checks asset presence and
   ZIP/installer consistency only.
2. **Real macOS execution.** LaunchAgent install/start/restart and the typed
   voice-unsupported path; macOS is not wired into the release gate.
3. **Signed artifacts.** The v0.0.6 policy remains the explicit unsigned
   exception unless the owner supplies an approved signer fingerprint and
   `--sign`/`--verify-signatures` run with `gpg`.
4. **Live service behavior.** The gate installs into a throwaway prefix/HOME
   and never starts a service. A running dashboard, voice bridge, orb, or
   gateway must be exercised separately.
5. **GitHub-hosted CI execution.** The gate and workflow steps exist, but the
   hosted runners remain subject to the account-level Actions blocker recorded
   in `docs/STATUS.md`.
