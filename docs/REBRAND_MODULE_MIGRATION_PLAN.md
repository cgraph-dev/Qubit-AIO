# REBRAND — MODULE-TREE MIGRATION PLAN

**Scope:** the `hermes_*` → `qubit_*` module-tree rename and its relationship to the `adapters/`
registry. **This document renames nothing.** It is the plan a future, gated change executes.

- Worktree: `/tmp/y8`, branch `y8`, base `1d3059c4` (main tip).
- Baseline: `python3 scripts/gate_all.py` → **PASS 5/5** (recorded before this doc was written;
  the doc changes no source, so it holds after).
- Every count below carries its **METHOD** in the adjacent column or sentence. No percentage is

## 0. THE FINDING THAT REFRAMES THE TASK

**The module-tree rename is already done.** `hermes_cli`/`hermes_state`/`hermes_platform` do **not
exist as importable packages** in this tree — the packages are `qubit_runtime/qubit_cli/`,
`qubit_runtime/qubit_platform/`, and the flat `qubit_runtime/qubit_state*.py` family. All 19999
tracked files contain **zero** `import hermes_*` statements in production code (verified below).

METHOD: `git grep -nIE '^[[:space:]]*(from|import)[[:space:]]+.*\bhermes_(cli|platform|state|runtime)\b'`
returns **14 match-lines / 9 files**, and *none* is production code: 8 are the vendored upstream
docs mirror (`qubit_runtime/website/docs/**`) plus 2 nix files generated by a build script, and the
remaining 4 are the deliberate alias-import test (`tests/test_agent_compat.py`, see §5).

What remains is **not a rename to perform — it is a compat surface to preserve and extend.** The
1821-line figure in `docs/REBRAND_AUDIT.md` (§iii) counts *match-lines* for module/symbol *patterns*,
which are dominated by (a) the `voicebridge/agent_compat/` adapter layer that *deliberately* speaks
the foreign names, (b) docstring provenance citations, and (c) audit tooling under `scripts/`. This
plan therefore addresses two distinct things:

1. **What to rename** — a residual, small, code-identifier set (and the "rename" is mostly
   *deleting provenance prose*, not moving modules).
2. **What must NEVER be renamed, and must be kept working for foreign content** — the wire
   contracts (§4) and the `HermesCLI`/`get_hermes_home`-family aliases (§2, §5).

> Consequence for method choice: the rewrite is **not** thousands of risky edits. It is: *halt the
> aliasing at the boundary already built, remove stray prose, and gate it.* The dangerous work was
> the rename that already happened; that is why §2's method is "shim, then freeze" rather than a
> second big-bang.

## 2. THE SAFE METHOD

### The three candidates

| Option | Shape | Verdict here |
|---|---|---|
| **Big-bang rewrite** | one commit renames all packages + every call site | **REJECT** — see below |
| **Two-phase rename with import gate** | phase 1: add new names, keep old as shims; phase 2: delete shims | rejects the *already-done* rename |
| **Compatibility shim, held at the boundary** | keep a legacy-name shim that re-exports the real modules; make the boundary explicit and testable | **CHOSEN** |

### Why the shim wins *for this repo*

1. **The rename is already complete; a new big-bang would be a second rewrite of already-correct
   code.** The repo's own record (`HANDOFF.md` §2) states 678 files / 3254 importers were renamed
   with "0 real `hermes_*` imports remain". Re-touching 400 files to reach the same state is pure
   risk for zero gain.

2. **The repo's history is defined by the silent-revert and half-rebrand bug classes, and the shim
   is the only option that is falsifiable at every step.** `HANDOFF.md` §4 enumerates four classes
   that each *shipped at least once*:
   - *(1) name loaded but bound nowhere* — the `qubit_id` incident: a rename that left a reader
     reading a name nothing produced.
   - *(2) sibling site left stale* — one hook fixed, siblings not.
   - *(3) test asserts what the product does not read*.
   - *(4) shadowed/duplicate definition* — invisible to name-existence audits.
   A big-bang rename reproduces class (1) exactly (the `qubit_id`→`hermes_id` incident the brief
   cites *was* a wire contract taken by a rename). A shim **cannot** produce class (1): the old
   name keeps resolving because the shim binds it.

3. **The shim already exists — and it is the *correct* shim, because it preserves module IDENTITY.**
   `voicebridge/agent_compat/framework.py` `ImportAliaser` binds `hermes_cli` and `qubit_cli` to
   the **same module object** (`sys.modules[alias] = sys.modules[target] = real`), with the reason
   written in the header: *"a foreign plugin that mutates the registry is mutating the live
   registry, not a private copy."* Class (4) *is* the duplicate-module bug this guards. Reusing it
   is reusing a mechanism that was built against this repo's specific failure.

4. **A shim is reversible and one-directional.** `ImportAliaser` also documents the two load-bearing
   inversions: *"a blanket string substitution is what corrupted 172 third-party URLs"* and
   *"failures are loud — never return a placeholder module."* The shim is an allowlist, so the
   class of "the sweep took a wire contract with it" cannot occur: a renamed token is either in the
   allowlist (safe) or absent (the sweep never touches it).

### The chosen method, precisely

**Make the compat surface an explicit, in-tree, tested shim package, and freeze the tree behind it.**

- **Do NOT add `hermes_cli.py` / `hermes_state.py` / … shim *files* to the repo root.** The existing
  `ImportAliaser` (a `sys.meta_path` finder) already resolves these names *without a file* and
  without polluting the tree — a file-based shim would create a *second* module object when both
  spellings are imported (class 4), which is precisely the bug `ImportAliaser.preload()` exists to
  prevent.
- **Do** make the boundary *load-bearing and stated*: the aliasing is installed via
  `install_for(...)` when foreign content is detected, and Qubit's own code must never import it
  (`agent_compat/__init__.py` rule 5, enforced by `tests/test_agent_compat.py`).
- **Do** keep the two in-tree *symbol* aliases that are not module-level: `HermesCLI = QubitCLI`
  (`qubit_runtime/cli.py:1808`) and the `get_hermes_home` family (`qubit_runtime/qubit_constants.py`
  ~192-203). These are **not** module aliases and the `ImportAliaser` cannot synthesise them; they
  are deliberate and cost one line each.

This means the execution phase is: **remove stray provenance prose, add nothing to `sys.path`, and
gate the boundary** — not "rename 400 files".

## 3. THE ORDER OF OPERATIONS

Ordered so each step is independently gateable and no step depends on a later one.

**Phase 0 — establish the baseline (no edits).**
Run `gate_all.py`; record PASS. Build the exclusion list into the audit script (§4) so every later
count excludes it.

**Phase 1 — leaf provenance prose (lowest risk, no runtime effect).**
Remove/reword `hermes_cli` mentions inside **docstrings and comments** (bucket §1c-(c), 18 lines,
mostly `voicebridge/*` and `qubit_runtime/qubit_cli/*_mixin.py` headers). Leaves = docstrings and
comments have no importer. Gate after: unchanged gate + import-everything sweep.

**Phase 2 — dev tooling under `scripts/` (not shipped).**
`scripts/` carries `hermes_cli` strings for sync/audit tooling (12 files). These are dev-only; rename
at leisure. Gate after: unchanged gate.

**Phase 3 — the `HermesCLI` docstring body (66 non-test lines).**
Reword docstring mentions to `QubitCLI` while **keeping `cli.py:1808 HermesCLI = QubitCLI`**. Do NOT
touch the tests (430 lines) — they assert the alias contract. Gate after: **`tui_gateway` import
check** (§5) because `slash_worker.py:36,179` bind `HermesCLI` at module scope; a stray deletion
there breaks all slash commands.

**Phase 4 — the alias tests and the boundary (the contract itself).**
No rename. Confirm `tests/test_agent_compat.py` still proves identity both import orders, and that
`adapters/test_registry.py` still finds every seam file. This is the phase that *freezes* the shim.

**Leaf-before-parents rationale:** docstrings → dev tooling → the class's prose → the contract. Each
earlier step's only readers are the later steps' instruments; nothing in Phase *n* is imported by
Phase *n+1*. This is the inverse of a big-bang, where a package rename and its importers change in
the same commit and a single miss breaks the whole tree at once.

| — | `scripts/check_half_rebrand*.py` | names loaded but bound nowhere (class 1) |
| — | `scripts/check_stale_daemons.py` | running processes older than their own fixes (report-only) |

### The gate that IS the proof for this migration

The operation that most directly proves safety is **the import-everything sweep at the scale of the
one that just validated 450 modules** (`scripts/safe_import_walk.py`, run with an isolated
`--home`). Rationale is in the script's own header: an import walk **is code execution**, so it runs
each import in a subprocess with a hard timeout and skips side-effecting modules by an explicit,
reason-bearing deny list (`update_cmd_fleet.py` ran the updater once — the incident the script
exists to prevent). For a module-tree change, "every module still imports" is the closest thing to
a proof that no importer was orphaned.

**Per-phase rule:** a phase is allowed to land only if `gate_all.py` PASS **and** the sweep's
failure set is identical to the baseline's (no NEW failure). A phase that does not move the failure
set is a no-op and must be reverted.

### Rollback

- **Per-phase, file-scoped.** Each phase touches disjoint files; rollback is
  `git revert <phase-commit>` — never `git stash` (repo-global across worktrees; corrupted two trees
  this campaign) and never `git add -A` (a prior salvage deleted `opencode.json`/`vercel.json` that
  way). **Commit per file.**
- **Signature to watch:** *a commit that deletes more than it adds is a silent-revert signature.*
  Screen every phase commit for net-negative line counts before merging.
- **No phase is allowed to edit the exclusion list.** If a diff touches a §4 token, the phase is
  rejected regardless of gate result — the gate cannot see a wire contract that an external reader
  depends on.
- **Services:** no phase restarts or stops a service. The systemd/launchd names in §4 change only
  through the *update/recovery migration path* (a separate, owner-authorised change) — never here.

## 6. THE ADAPTERS END-STATE

### How `adapters/` relates to the renamed tree

`adapters/` is a **registry + documentation scaffold**; it owns **no runtime code today**
(`adapters/README.md`, `registry.yaml` header). The five discovery seams it records are the *real*,
*current* entry points the runtime calls — and every one of them points into the **already-renamed**
tree:

| kind | seam (renamed tree) | symbol |
|---|---|---|
| skills | `qubit_runtime/tools/skills_tool.py:248` | `skills_list` |
| plugins | `qubit_runtime/qubit_cli/plugins.py:1770` | `discover_plugins` |
| mcps | `qubit_runtime/tools/mcp_tool_discovery.py:595` | `discover_mcp_tools` |
| channels | `qubit_runtime/gateway/platform_registry.py:414` | `PlatformRegistry.create_adapter` |
| tools | `qubit_runtime/tools/registry.py:96` | `discover_builtin_tools` |

`adapters/registry.py` is **not wired into the runtime** (by design). `adapters/test_registry.py`
asserts every recorded seam file exists — so a future move of a seam fails loudly rather than the
registry silently lying. **This is why the module migration must not move any of these five files
without updating `registry.yaml` in the same commit.**

### What a new adapter plugs into

An openclaw/picoclaw adapter **does not invent a parallel discovery mechanism** — it reuses the five
seams above (per `adapters/README.md` "How a future adapter plugs in"):

1. Add a `registry.yaml` entry: `name: openclaw`, its `kind`, and the seam above it hooks.
2. Put ported code under `adapters/openclaw/` (the folder is the namespace; it is *not* on
   `sys.path`, so import it as a package or install it as a plugin/MCP per the kind).
3. Flip `status: planned → shipped`.

For `skills`/`plugins`/`channels`/`tools` the lowest-friction path is for the ported adapter to **be
a plugin** (`plugins/<source>/` exposing `register(ctx)`), because plugins already plug into all
four seams; `adapters/<source>/` then documents and re-exports it. For `mcps`, the adapter is an MCP
server config entry.

**Relationship to the foreign-name shim:** the *Hermes* adapter's naming tables live in
`voicebridge/agent_compat/adapters/hermes.py` (pure data) and are consumed by
`voicebridge/agent_compat/framework.py`. A new `openclaw`/`picoclaw` adapter is *one more
`ForeignAdapter` instance* — usually pure data, no new engine code. That is the whole point of the
framework (`agent_compat/__init__.py`): the second adapter is a data file, not a rewrite.

**Existing code has NOT moved.** `qubit_runtime/acp_adapter/` is the one adapter-shaped module that
ships; it stays put until a planned `acp_adapter → adapters/acp/` migration runs as its own gated
change (README "Existing code has NOT moved"). **That future move is a module-tree change and must
follow §3's order and §5's gate.**

## 7. THE SINGLE BIGGEST RISK

**Executing this as if the rename were still pending.** The framing "~1821 lines / ~400 files to
rename" invites a big-bang rewrite. Applied to a tree where the rename is *already done*, a
big-bang would (a) reproduce the `qubit_id` class — a name loaded but bound nowhere — and (b) walk
straight through the §4 wire contracts, because the exclusion list is invisible to a mechanical
sweep. The prior `qubit_id`→`hermes_id` incident is exactly this: a rename that took a wire contract
with it and broke a running system.

**Mitigation:** the plan's central move is to *stop renaming* and *freeze the boundary* (§2). The
execution phase is prose removal + gating, not a rewrite. Every phase must pass `gate_all.py` **and**
the import-everything sweep with an unchanged failure set, and no diff may touch a §4 token.

**Secondary risk (worth naming):** the module-scope `from cli import QubitCLI as HermesCLI`
bindings in `tui_gateway/slash_worker.py:36,179`. A well-meaning "remove the `HermesCLI` alias" edit in Phase 3 breaks
*every* slash command at once, and the import gate catches it only because it imports `cli` — the
lazy-import check is the instrument that must be green before that phase lands.
