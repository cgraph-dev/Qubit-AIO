## 3. THE BUG CLASSES THAT ACTUALLY BIT US TODAY

### 3a. Half-finished rebrand -> NameError on an entire feature

A rename touched a helper's PARAMETER but not its CALL SITE. The call site then
references a name bound nowhere:

    model_switch_providers.py:846  _raw_pool_usable(qubit_id, ...)   -> hermes_id
    model_switch_providers.py:887  _credential_pool_is_usable(qubit_slug) -> hermes_slug

Effect: the model picker returned **0 providers with a 500** (`name 'qubit_id' is not
defined`). Both sat in the section-1 builtin-row path, so the picker showed "0 / 0"
rather than a partial list.

DETECTOR (run this after any rename wave; it found both):
    parse each module with ast; for every function, collect bound names (args, assigned
    Names, imports, except targets, comprehension targets) plus module-level names plus
    builtins; report every Name-Load not bound. Ignore lambda params and comprehension
    vars if your collector is naive -- they are false positives.

Any hit is a probable live crash. Prefer this over reading diffs: a rename that misses
one use looks correct in review.

### 3b. Silent clobber -- newer code reverted without a conflict

Commit 65d72246 (voice/orb work) DID NOT just add code: it DELETED newer work in two
files (`tools/computer_use/backend.py` lost `ComputerUseProvider` + its ProviderBase
import; `permissions.py` lost the whole multi-backend path). Git merged without
conflict because the other side never touched those files, so it took the only side
that had changed. See docs/CLOBBER_FINDING.md.

The reliable signature is **deletions > additions**, NOT "branch A is an ancestor of
branch B". An earlier checker using ancestry flagged **14 files, 2 real** -- a checker
that noisy trains you to ignore it.

### 3c. Clean auto-merge carrying STALE content

`observability/schemas/hermes.shared_metrics.v3.schema.json` auto-merged cleanly to the
STALE `hermes.*` consts, because HEAD never edited it (base == ours, so git took theirs).
A clean auto-merge is NOT a conflict, so nothing flagged it -- and it silently failed 8
tests. The same file later lost the `one_shot` enum member the same way (fixed in
b8a10b7a). After ANY merge, diff the merged result against BOTH sides for files that
auto-merged without conflict.

### 3d. Multi-writer -- three agents fixed /qubit-chat simultaneously

The VS Code opencode session, plus my agents 1 and 2, all independently implemented the
chat live-update path and the D1/D2/D3 chat fixes. Both implementations were correct and
incompatible. Resolve by picking the richer primitive per file, not by side. Before
dispatching, check `git status` mtime: a file written seconds ago means someone is mid-write.

## 7. ORDERING: PORT -> DELETE -> REBRAND (do not reorder)

Porting gets capability; rebrand gets naming. Deleting hermes needs only the first.

    HermesCLI = QubitCLI   (cli.py:1805)   <- rebranding that never happened, and nothing
                                              forces it to. Delete hermes with this line
                                              still present; it will keep working.
    703 HERMES_* env vars, 733 `.hermes*` path refs  <- compat surface, can stay forever

Rebrand is HARDER than the thing it appears to be a prerequisite for, because it needs
migrations:
  * `.hermes-update-in-progress` is shared BYTE-FOR-BYTE by Python update_lock.py,
    Rust paths.rs:90, and Electron update-marker.ts:34. Renaming Python alone lets two
    updaters run concurrently and corrupt the install.
  * Renaming HERMES_HOME breaks every existing user config.
  * Deleting a compat alias breaks every imported call site.

So: finish the port, run the deletion test, retire hermes. Rebrand afterwards,
incrementally, with migrations, starting with the ~43 user-visible strings. Legal
attribution (`@NousResearch` MIT comments) MUST STAY per docs/BRAND.md.
