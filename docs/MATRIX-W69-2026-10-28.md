## Runner inspected

`qubit_runtime/scripts/run_tests_parallel.py` — one `python -m pytest <file>` subprocess per test
file, bounded parallelism, discovery excludes `integration/`, `e2e/` and `docker/`, default file
timeout 300 s, one retry of a failing **file** (pass-on-retry is reported FLAKY), pytest exit 5
("no tests collected") treated as a pass. `repo_root` is always `qubit_runtime/`, so runtime tests
are run with `--paths` relative to it. The documented `-v` internal error (a monkeypatched
`shutil.get_terminal_size`) means all runs used `-q`.

Deviation from the canonical command: `-j 8` instead of the default 16 (the host was already at
load ~14), and a 240–300 s per-file cap. Both only make the run more conservative; they are why
several slow files timed out and then passed alone.
