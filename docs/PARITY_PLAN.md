# Plan — byte-for-byte parity against three upstream repos, under rebrand

Owner directive: three upstream projects must work **1:1** inside Qubit. UI is
1:1 *visually*; everything else is 1:1 *behaviourally*, rewired onto Qubit's own
backends and owned by Qubit — not a separate server next to it.

- `joeynyc/hermes-hudui` → **Qubit Office** (`hudui was for qubit office`)
- `nesquena/hermes-webui` → the workbench chat surface
- `abundantbeing/hermes-browser-extension` → the browser companion

| WebUI → workbench | `f328d3f8e17f92a72fd71cc05f1e45665f2bc662` (2026-11-06) | **2552** | **108** | `voicebridge/workbench_ui/` |

**The HUD gap is the whole job.** 3 files is one hand-written JS bundle
(157 KB) that reimplements panels against Qubit routes. Upstream is 92 backend
files + 54 frontend files + 35 tests — a React app with `ChatPanel`,
`CommandPalette`, `CronCreateDrawer`, `BootScreen` and a per-panel API module.

Those three files are **not** a port of upstream. They are a from-scratch
reimplementation that happens to cover the same tabs. "Byte with byte" cannot
be claimed against them, and that is the single biggest correction this plan
makes.

WebUI's 108 files are a partial port: upstream is a 2,056-file Python server
plus a JS frontend; ours carries the static UI and a subset of routes.

## What "1:1" can and cannot mean here

State this before any agent starts, because it decides every argument later:

1. **Visual 1:1 is literal.** Markup, class names, CSS, spacing and component
   structure come from upstream unchanged. Only brand strings, product names,
   icons and colours tied to identity may differ, and each substitution is
   listed in a manifest.
2. **Behavioural 1:1 is a contract, not a byte diff.** Upstream's backend opens
   `state.db` read-write and imports its own agent. Qubit has one session
   authority and its own agent. Byte-identical backend code would mean two
   writers on one database. So: upstream's *routes, request shapes, response
   shapes, status codes and side effects* are preserved exactly, while the
   implementation behind them calls Qubit's authorities.
3. **A route upstream has and we lack is a gap.** A route we have that upstream
   does not is either a deliberate Qubit addition (recorded) or a defect.

Therefore the deliverable is not "identical bytes". It is: **every upstream
file either present-and-faithful, or present-and-rewired-with-the-rewiring-
listed, or explicitly declined with a reason.** Anything else is a gap.

## Phases

### Phase 0 — build the parity ledger before touching code

No agent writes implementation code until this exists. It is the instrument
every later claim is measured with, and building it first is what stops the
"green but unfaithful" failure this repo has hit before.

Output: `docs/PARITY_LEDGER.json` + `docs/PARITY_LEDGER.md`, generated by
`scripts/parity_ledger.py`, one row per upstream file:

```
upstream_path, surface, kind (backend|frontend|test|asset|doc),
status (ported|rewired|missing|declined|absent-at-pin),
our_path, upstream_lines, our_lines, line_delta,
verified_by (test name or 'none'), notes
```

Rules that make it trustworthy:

- `ported` requires an identical-normalised diff: same top-level definitions,
  same route strings, same response keys. Brand-only differences are allowed
  and recorded in the substitution manifest.
- `rewired` requires the row to name **what was replaced and with what**
  (`state.db` → `QubitSessionStore`, `run_agent.AIAgent` → `chat_transport`).
- A row that is `ported` with `our_lines == 0` is a lie the generator must
  reject outright.
- Regenerate, never hand-edit. The ledger is derived from `git ls-tree` on both
  sides.

Acceptance: the ledger accounts for **209 + 2552 + 1178 = 3939** upstream files
with no row leaving `status` empty, and its totals reconcile against
`git ls-files` on each clone.

### Phase 1 — HUD → Office, the real port (largest)

Upstream is a React app. Qubit Office is a Habblaud iframe plus a compiled game
bundle. The honest options are:

- **A. Port upstream's React app into Office as a sub-view.** Bring `frontend/src`
  across, rebrand, mount it at an Office route. Keeps markup 1:1 by
  construction and makes the visual claim checkable. Backend goes through
  Qubit routes phase 1 also builds.
- **B. Keep the hand-written bundle and declare it a reimplementation.** Cheaper,
  contradicts the directive.

Plan for **A**, because it is the only one that satisfies "1:1 UI".

Workstreams, each independently verifiable:

1. **Backend routes.** Port upstream's 92 `backend/api/*.py` onto Qubit's
   compat dispatcher. The tab set is known: health, sessions, cron, models,
   skills, plugins, cron, corrections, patterns, replay, providers, projects,
   profiles, memory, gateway, agents, dashboard, chat, cache, serialize.
   Many already exist under `/agent/api/hud/*`; the work is fidelity, not
   greenfield. Where upstream reads `state.db` directly, bind to
   `QubitSessionStore`.
2. **Frontend.** Port `frontend/src` (54 files) into Office: App shell, panels,
   command palette, boot screen. Rebrand text and icons only.
3. **Mounting.** One Office route serving the ported app; verify it renders in
   the live Office iframe, not just in isolation.
4. **Tests.** Port the 35 upstream tests where they assert behaviour we can
   reproduce; add connector tests for the routes upstream lacks.

Risk to state up front: upstream's `ChatPanel` overlaps the workbench chat from
phase 2, and Office already has an agent panel. Resolve by making the HUD chat
panel **read-only or routed to the workbench**, not a third chat implementation.
Decide this before building it, not after.

### Phase 2 — WebUI → workbench, close the route set

Ours is a partial port with known typed refusals. Work:

1. **Enumerate every route upstream serves** from its `api/routes.py` and diff
   against ours. Produce the missing list.
2. **Classify each missing route**: portable onto Qubit authorities / needs a
   new Qubit authority / declined. Anything declined gets a reason, in the
   ledger, not a silent 501.
3. **Implement the portable ones**, preserving upstream's request and response
   shapes exactly.
4. **Port upstream's tests** for behaviour we keep.
5. **Frontend:** close the visual gap against upstream's own UI (the icon rail,
   sidebar filters, reasoning traces, Files/Artifacts/Todos panel are the known
   deltas). Do not invent panel content upstream does not have.

Known already: `chat/status` is not ported; several other routes answer typed
501s. Those are the first rows of the missing list.

### Phase 3 — Extension, close 470 → 1178

Ours carries 470 files of a 1178-file project. Work:

1. **Diff file lists.** Identify what is missing — the biggest bucket is
   `813 .mjs` upstream.
2. **Separate runtime from build.** Some upstream `mjs` files are build output
   or generated; porting them as source would be wrong. Classify before
   copying.
3. **Port the real gaps**, rebrand, keep the 27 tools and 3 hooks wired.
4. **Verify over HTTP**, not just import: the plugin must report its counts
   from the live gateway.

### Phase 4 — Independent verification (the phase that decides)

A separate read-only verifier per surface, whose only job is disproving the
port. This is the role that caught 43% fabricated files on a previous batch.

Each verifier must:

- Prove every claimed file **exists at the pin**: `git cat-file -e <pin>:<path>`.
  A path upstream lacks cannot be a port of anything.
- Compare **top-level symbol sets** per file and report names we have that
  upstream lacks.
- Compare **line counts**, and treat a large delta as a finding to explain.
- Check route tables both directions: upstream routes we lack, and ours that
  upstream does not have.
- Be told explicitly: *a green import proves nothing*; report counts you
  measured, not counts you expected.

Then **re-derive the verifier's findings by hand** before acting on them. Its
output is a claim like any other.

### Phase 5 — Connector verification (the seam, after merge)

Every lane can pass in isolation and the merged tree still be broken. After
merging:

- Drive each surface through the **real** entry point — live Office iframe,
  live workbench page, live gateway plugin status — and assert a real payload.
- Compare bytes served against bytes on disk for static assets.
- Run one turn end to end on each chat surface.

## Agent dispatch

One `git worktree` per agent; explicit paths when staging, never `git add -A`.

| Agent | Scope | May write |
|---|---|---|
| `ledger` | Phase 0 generator + ledger | `scripts/parity_ledger.py`, `docs/PARITY_LEDGER*` |
| `hud-backend` | Phase 1.1 | `qubit_runtime/plugins/qubit-hud/**` (routes), `voicebridge/hud/**` |
| `hud-frontend` | Phase 1.2–1.3 | `frontend/qubit-app/plugins/qubit-hud/**` |
| `webui-routes` | Phase 2.1–2.3 | `voicebridge/workbench_ui*` |
| `webui-ui` | Phase 2.5 | `voicebridge/workbench_ui/static/**` |
| `ext-port` | Phase 3 | `frontend/qubit-app/plugins/qubit-browser-ext/**` |
| `verify-hud` | Phase 4 | read-only |
| `verify-webui` | Phase 4 | read-only |
| `verify-ext` | Phase 4 | read-only |

Dispatch order: `ledger` first and alone — every other agent reads its output.
Then the three port lanes in parallel. Then the three verifiers in parallel,
after the port lanes merge.

Each port agent gets in its task text: the pin SHA, its exact file list on
disk, the rebrand rules, the ledger row format, and **"skip and report rather
than guess — a wrong port is worse than a missing one."**

Verifiers get: the pin, the claim set to test, and the instructions above.

## Definition of done

- Ledger rows: **3939**, every one with a non-empty status.
- No `missing` row without a recorded decision; no `declined` row without a reason.
- Brand substitutions listed in one manifest; zero legacy brand strings on
  visible surfaces.
- All three surfaces driven live, with the output pasted into the ledger's
  evidence column.
- A statement of what is *not* 1:1, in plain words, at the top of the report.

## What this plan refuses

- Calling the current 3-file HUD a port of a 209-file project.
- Claiming behavioural parity from a byte diff on code that cannot run here
  unchanged.
- Any agent's "done" being accepted without a pin check.
