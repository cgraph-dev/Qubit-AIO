## Owner criteria for OPERATOR_ONLY

A row is `OPERATOR_ONLY` only when **all** of the following hold:

1. the code path is complete and hermetic-tested through an injected transport,
   actuator, or probe seam;
2. execution requires a genuine live prerequisite — live credentials,
   hardware, an account, OAuth, CAPTCHA/2FA, or another real operator
   dependency that cannot be synthesized hermetically;
3. the code returns a **typed** unavailable/refusal state/code when the live
   dependency is absent (never a fabricated success and never a raw crash);
4. the exact manual procedure and expected evidence are documented here; and
5. the row stays visible in the ledger and is never reclassified to
   `IMPLEMENTED`.

A row that fails any criterion is reported in the **Criteria compliance report**
below rather than hidden.

## Per-row qualification procedures

Common conventions:

- Repo root: `/home/trick/Projects/Repos/qubit-voicebridge`.
- Canonical CLI: `.venv/bin/qubit` (entry point `qubit = voicebridge.cli:main`,
  `pyproject.toml:72`).

  `.venv/bin/pytest -q <proving test>`.
- Expected evidence per row: captured command output (JSON with the typed

  receipt where the surface emits one. Store evidence outside the repository
  or in a disposable directory; never commit credentials or state.

### 1. `OC-13` — Real desktop control (Peekaboo/CUA)

- **Capability:** controlled desktop actions through a pinned computer-use
  actuator.
- **Live prerequisite:** hardware — a graphical X11/Wayland session plus an
  operator-provisioned, pinned accessibility actuator/driver. No unpinned
  driver is downloaded by Qubit.
- **Code path:** CLI `computer-use` → `voicebridge/computer_use.py` (status,
  doctor, permissions, `refuse_install` at `:144`); voice
  `computer_status/doctor/permissions/install_refusal`.
- **Typed unavailable:** `COMPUTER_USE_NO_DRIVER` (`voicebridge/computer_use.py:29`).
- **Hermetic proof:** `tests/test_computer_use8tf.py` (`test_install_refused`,
  `test_doctor_checklist_typed`).
- **Procedure:**
  1. On the graphical host run `.venv/bin/qubit computer-use status` — expect
     `control == "DISABLED"` and honest `display_present`/`atspi_reachable`.
  2. Run `.venv/bin/qubit computer-use doctor` — expect four checks with
     `OK/DEGRADED/MISSING`.
  3. Run `.venv/bin/qubit computer-use install` — expect
     `state=REJECTED, code=COMPUTER_USE_NO_DRIVER` and confirm nothing was
     downloaded/installed.
  4. With the operator-provisioned pinned actuator present and confirmation
     wired, re-run the 8V accessibility path and capture an actual action
     receipt.
- **Evidence:** JSON output for steps 1–3; a checksum/path record for the
  pinned actuator; the action receipt for step 4. Without the actuator, step 3
  is the expected terminal evidence.
- **Rollback:** none required — no actuator was installed and no session was
  touched.
