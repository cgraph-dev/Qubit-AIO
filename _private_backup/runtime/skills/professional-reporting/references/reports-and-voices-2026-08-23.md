**Filler fast-path (the Yeah. / hello 4.6 s):** `"Yeah."` hit `intent.llm` (`qwen3-vl:8b` still 4.79 s on that one-word on the 3b) before `_handle_conversation` could bypass it. Fix: `routing.filler_fast` **before** `Classifier.classify()` in both `_route_intent` and `_process_web_utterance_inner` — `"hello/yeah/yep/ok"` → `_handle_conversation` directly, <100 ms, no LLM. Also switched classifier default `qwen3-vl:8b → huihui_ai/llama3.2-abliterate:3b` (resident, `hello` 0.54 s). This is the first hello slowness root cause — don't regress it.

**STT fallback (chars 0 while peak 0.26):** `sherpa/parakeet` can blank on a real wav (2.37 s, loud but `chars 0`). Added `_transcribe_with_fallback()` — retry once with the *other* low-resource engine (`parakeet ↔ moonshine`, 48-172 ms) instead of `"I didn't catch that."`; true silence stays empty. Bench: `moonshine` 0.05 s is best fallback vs `faster-whisper base` 0.46 s / `small` 1.21 s / `large-v3-turbo` 5.05 s. Also `vad.rms_gate 0.0018→0.0015` for soft syllables.
