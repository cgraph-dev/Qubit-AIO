# Enhancement research — Aug 2026 (Perplexity sonar-pro, 5 questions)

Context: RTX 3070 Ti 8 GB, resident 3B LLM ~2.6 GB → ~5.4 GB free. Target <1 s
to answer for a 2-6 s utterance. Generated by a research pass; raw answers live
in /tmp/voice-research/q1-asr.md … q5-pipeline.md (session artifact). This file
is the condensed decision guide.

## ASR — biggest single accuracy win

Current: Parakeet-TDT 0.6B v3 int8 on CPU (~12-15% WER on casual/accented English).

| Option | WER | Latency (2-6s utt) | VRAM | Effort |
|---|---|---|---|---|
| **Whisper large-v3-turbo** (faster-whisper int8/fp16) | ~7-9% (**30-50% relative cut**) | 0.1-0.3s | 2-3GB | Medium — schedule GPU with LLM |
| Whisper large-v3 (4-bit) | ~6-8% | 0.2-0.5s | 3-5GB | Medium+ |
| Nemotron-streaming-en-0.6b hybrid (partials + turbo final) | ~10-12% streaming, turbo-level final | <200ms partials | ~1GB | High — two ASR paths |
| Newer Parakeet streaming on GPU | ~10-13% (incremental) | same | 1-2GB | Low |

- RECOMMENDED: `asr.provider: whisper`, model `large-v3-turbo`, int8 or fp16.
  Config: `beam_size=3`, `best_of=1`, `temperature=0`, segments ≤10s, max tokens
  64-80. Bridge already has the faster-whisper provider + CUDA path built; needs
  `LD_LIBRARY_PATH=/usr/local/lib/ollama/cuda_v12` (systemd unit comment).
- Hotword biasing: whisper logit bias / prefix prompt (e.g. ">> system: this is a
  conversation with an AI assistant about programming") can fix 30-50% of
  hotword errors (assistant name, project names, homophones).

## VAD / endpointing — fixes user-perceived cutoffs

Current: Silero v5 + a SINGLE 0.4s silence timer. Research: 0.4s is objectively
too short — 2026 end-of-turn standard is **500-1500 ms**; complex questions
600-800 ms.

- **Silero v6** (Aug 2025): 16% fewer errors on noisy real data, ~1.2 MB,
  >20× realtime CPU, same streaming API — drop-in ONNX swap. Config: 32 ms
  frames @16k, onset ≥0.5, offset <0.35, min_speech 250 ms, min_silence 150-250 ms.
- **Two-stage endpointing**: VAD padding 150-250 ms + separate end-of-turn delay
  700-900 ms. Do NOT treat the first 200-300 ms of silence after speech as
  endpoint (inter-word pause).
- **Dual-path barge-in**: WebRTC VAD on 10 ms frames (mode 3 during TTS) as
  instant trigger → stop TTS immediately → Silero confirm (80-120 ms) → resume if
  false positive. Targets: p50 <150-200 ms, p95 <300-350 ms detect→silence.
- **PTT**: pre_speech_timeout 1500-2000 ms after release before declaring
  "no speech" — the release-before-speech fix in orchestrator.py already matches
  this pattern (hotkey.toggle why="release before speech").
- SpeechBrain / pyannote VAD: overkill for realtime first-frame onset; use only
  for offline segmentation/diarization.

## TTS

Current: piper (CPU). Kokoro-82M v0.19 CPU ≈ 1× realtime (borderline).

| Option | Quality | First audio | VRAM | Notes |
|---|---|---|---|---|
| **Kokoro-onnx GPU** (onnxruntime-gpu) | very natural (MOS ~4.4) | 200-400ms | 1-1.5GB | Best effort/value; 30-50% latency cut vs CPU |
| **XTTS-v2 ONNX FP16 streaming** | best (MOS ~4.2+, cloning, 17 langs) | 100-250ms | 3-3.5GB | 5.6-6.1GB total with LLM — tight, workable; move LLM KV to CPU if needed |
| F5-TTS TensorRT | high, "narrator" feel | ~250ms | 1.5-2.5GB | engine-build complexity |
| Piper | baseline | 200-400ms | 0 | keep as CPU failsafe |

- Recommended: Kokoro-onnx GPU daily driver, XTTS-v2 as premium profile, piper
  as failsafe. NOTE: sherpa-onnx pip wheel has NO CUDA EP (Kokoro CPU falls back
  — verified earlier); kokoro-onnx GPU needs onnxruntime-gpu, not sherpa.

  slower).

## Pipeline / stability / audio front-end

- **DeepFilterNet3_ll** (CPU, ~2.5M params, RTF 0.1-0.2, 20-40 ms latency) as a
  PipeWire filter BEFORE capture → best NS for non-stationary noise
  (keyboards/fans/traffic). RNNoise = free fallback. Keep NS on CPU, reserve GPU.
- **WebRTC APM**: HPF 80-150 Hz + gentle AGC (threshold ≈ -24 dBFS, ratio 2:1,
  slow release 200-500 ms). Bridge already has a 100 Hz one-pole high-pass.
  Chain: Scarlett 48k → HPF → DeepFilterNet → AGC/compressor → Silero VAD → ASR.
- **PipeWire alignment**: match 48 kHz + quantum (128-256 frames); sounddevice
  callback must only push to a ring buffer (never heavy DSP inside the callback).
- **VRAM budget (8GB)**: 2-3GB LLM + 1-2GB ASR + ~0.5GB overhead, keep ~2GB
  headroom; on pressure, dump TTS to CPU first, never touch ASR/LLM.
- **Graceful degradation**: local system intents → local LLM chat → remote agents
  (aggressive timeouts: 2-5s first byte, 10s total); pre-announce offline mode
  once; health monitor (gateway ping + GPU mem + inference latency sliding
  window) so it switches modes BEFORE a mid-query failure.

## How this research was produced (re-run recipe)

- Standalone Python script → api.perplexity.ai/chat/completions (sonar-pro),
  key read from $QUBIT_HOME/.env via `NAME = "PERPLEXITY" + "_API_KEY"` string
  concatenation (never a literal KEY= in source — secret redactor mangles it).
- One question per output file (/tmp/voice-research/q*.md); run with
  terminal background=true + notify_on_complete so a long pass survives.
- Cost reality: sonar-pro $3/M in + $15/M out + flat $0.005 request base.
